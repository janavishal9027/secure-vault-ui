# Secure VAULT — Digital Notes Frontend

AI-powered, secure note management built for security and simplicity. Organize
knowledge, uncover insights with AI, and stay productive.

This is the **React** web client for the Digital Notes platform. It talks to a
set of backend microservices (authentication, roles, notes, and the AI core /
worker services) over REST.

---

## ✨ Features

- **Notes** — create, edit, search, sort, grid/list views, paginated dashboard.
- **AI Summary** — one-click summaries of long notes (generated by the AI worker).
- **AI Tags** — auto-generate and manage tags for a note.
- **Related notes** — semantic recommendations surfaced per note.
- **VaultGPT (AI chat)** — streaming chat answers (token-by-token), Markdown +
  syntax-highlighted code blocks, optional "use my notes as context" grounding
  with citations, and conversation management (rename, pin, archive/unarchive,
  delete).
- **Voice input** — dictate note content via the browser Web Speech API.
- **Auth & security** — JWT login, two-factor authentication (2FA), and OAuth
  sign-in with Google / GitHub.
- **Light / Dark mode** — app-wide theme toggle (in the profile menu), persisted
  across sessions.
- **Responsive** — adapts from desktop to mobile (collapsible drawers, fluid
  grids, condensed toolbars).

## 🚀 Getting started

### Prerequisites
- **Node.js 20+** and npm
- The backend services running (see [Backend services](#-backend-services))

### Install & run
```bash
npm install
npm start
```
The app runs at **http://localhost:3000**.

> **Windows / PowerShell note:** if `npm install` fails with
> *"running scripts is disabled on this system"*, allow scripts for your user
> (no admin needed):
> ```powershell
> Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
> ```
> Then open a **new** terminal, or use `npm.cmd install` in the current one.

### Other scripts
```bash
npm run build   # production build into ./build
npm test        # run the test runner
```

## ⚙️ Configuration

Backend URLs are provided via `REACT_APP_*` environment variables. CRA **inlines
these at build time**, so set them before `npm start` / `npm run build` (or pass
them as Docker `--build-arg`s). They fall back to localhost for local dev.

Create a `.env` file in the project root:

```ini
REACT_APP_AUTH_BASE_URL=http://localhost:3211   # authentication service
REACT_APP_ROLE_BASE_URL=http://localhost:3212   # roles service
REACT_APP_NOTE_BASE_URL=http://localhost:3213   # notes service
REACT_APP_AI_BASE_URL=http://localhost:8001     # ai-core-service
```

> Do not commit real secrets. This frontend only needs service URLs — API keys
> (Gemini / OpenRouter, JWT secret, DB credentials) live in the **backend**
> services, never here.

## 🔌 Backend services

The client expects these services (part of the Digital Notes backend):

| Service | Default port | Responsibility |
|---------|--------------|----------------|
| Authentication | 3211 | login, signup, 2FA, OAuth, JWT |
| Roles | 3212 | role-based access |
| Notes | 3213 | note CRUD |
| `ai-core-service` | 8001 | chat (streaming), tags, semantic search, recommendations |
| `ai-worker` | 8000 | background note summarization |

The AI services use a Postgres database with **pgvector** for embeddings, and an
LLM provider (Gemini / OpenRouter) configured server-side.

## 🎨 Theming (light / dark)

Theme is driven by CSS variables in `index.css` that swap on a `data-theme`
attribute on `<html>`. `components/theme/ThemeModeContext.jsx` toggles and
persists the mode (`localStorage` key `THEME_MODE`), and a small inline script in
`public/index.html` applies the saved theme before first paint to avoid a flash.
Toggle it from the **avatar → profile menu** in the top bar.

## 📦 Deployment

- **Docker** — multi-stage build (`Dockerfile`): builds the static bundle, then
  serves it. Pass per-environment URLs as build args:
  ```bash
  docker build \
    --build-arg REACT_APP_AUTH_BASE_URL=https://auth.example.com \
    --build-arg REACT_APP_AI_BASE_URL=https://ai.example.com \
    -t secure-vault .
  ```
- **Kubernetes** — `deployment.yml`, `service.yml`, `ingress.yml`.
- **CI** — `bitbucket-pipelines.yml`.
